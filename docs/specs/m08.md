# M08 local WAL, durable identity, and ACK boundary

`course/m08-start` freezes PLAN v0.10 as a structured RED. It does not contain the local runtime
implementation and it does not assert completion evidence.

The only new axis is a single-process, single-shard, caller-serialized runtime that will own a fresh
matching core and apply this order:

```text
validate canonical M08C1
-> durable identity preflight
-> append complete M08W1 record
-> FileChannel.force(true)
-> apply to matching-core
-> retain original canonical result
-> ACK
```

The canonical envelope binds producer id, positive epoch, shard, continuous producer sequence,
UUID command id, payload SHA-256, and the exact command payload. Exact known bindings replay their
original result; command-id, slot, and payload conflicts are stable pre-WAL rejections. A higher
epoch must begin at sequence one and fences unseen commands from prior epochs. Because sequences
are continuous and bindings are never evicted, every lower active-epoch slot is already bound: an
exact identity is a duplicate and another identity is a slot conflict. The reserved
`PRODUCER_SEQUENCE_STALE` code therefore has no fabricated direct coverage witness.

M08W1 freezes CRC32C-protected segment headers and records, positive contiguous segment/WAL/
application identities, no cross-segment record, force-before-rename and parent-directory force on
rollover, genesis recovery, orphan-temp rejection, final incomplete-tail repair, and fail-closed
complete or middle corruption. Every command that consumes `ApplicationSequence` must be journaled,
including Place with M07 STP fields, Cancel, Prepare/Activate RuleSet, ChangeMarketMode, and
MassCancel. Business rejection is still a durable application result.

The start inputs are exactly twenty fixed scenarios and a repository-owned SplitMix64 profile with
seed `5808`, 96 histories by 48 operations across four lanes, twenty-four obligations, ten required
semantic mutants, and five tutorial permalinks. Completion must add an independent no-I/O identity
model, a third durability ledger, deterministic fault injection, child-process halt smoke, strict
fresh-runtime shrink/replay, and annotated-tag-bound evidence. `SYSTEM_ERROR` can never count as a
mutant kill.

The child-process smoke is a process-crash/file-reopen check, not power-loss proof. Likewise,
`FileChannel.force(true)` is only the documented JDK/OS barrier. M08 excludes snapshot, retention,
replication, Aeron, leader election, quorum, failover, multi-shard routing, database double-write,
group commit, performance claims, and high availability.
