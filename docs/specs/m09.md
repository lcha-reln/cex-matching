# M09 snapshot, bounded suffix recovery, and whole-segment retirement

`course/m09-start` freezes PLAN v0.11 as a structured RED. It contains no production snapshot
implementation, no completion judge, no completion evidence, and no claim that M09 is complete.
M00–M08 remain the inherited executable baseline.

M09 adds exactly one complexity axis to the caller-serialized, single-process, single-shard M08
runtime: a quiescent local snapshot followed by bounded WAL-suffix recovery and safe retirement of
fully covered WAL segments. It does not change matching semantics, M08C1 ingress identity, M08W1
record semantics, or append/force/apply/ACK ordering.

## M09S1 state boundary

The only snapshot format in this unit is `M09S1`. A snapshot is captured synchronously between
commands while the runtime owns the single-writer boundary. It must contain enough state to make a
fresh runtime semantically indistinguishable from genesis replay at the same cut:

- the complete order registry, including resting, filled, and canceled identities;
- price-level membership, price-time FIFO, remaining quantity, execution policy, admission rule
  identity, participant group, and STP policy;
- next acceptance and application sequences;
- active and optional prepared RuleSet artifacts, control revision, and activation fence;
- market mode, mode revision, mode-transition fence, and Mass Cancel fence;
- both command-id and producer-slot bindings, producer epoch/sequence cursors, original canonical
  duplicate results, and their logical WAL positions;
- the M08 transcript digest and the semantic state digest at the snapshot cut; and
- snapshot generation, shard identity, last included WAL sequence, last included application
  sequence, encoding length, and integrity checksum.

Serialization digest and semantic digest are separate evidence. Byte equality proves a particular
`M09S1` encoding; semantic equality proves restored behavior and state. Unknown magic or version,
checksum failure, filename/header generation disagreement, wrong shard, impossible cut, or an
inconsistent state graph fails closed. M09 deliberately has no N-1 fixture, downgrade reader, or
format-evolution claim.

## Publication and authority

Snapshot publication is ordered:

```text
capture one command-boundary state
-> encode and write snapshot-<generation>.m09s1.tmp
-> FileChannel.force(true) the complete temporary file
-> atomic rename to snapshot-<generation>.m09s1
-> force the snapshot directory
-> only now make this generation eligible for WAL retirement
```

An orphan or partial temporary file is never authoritative. Recovery selects the highest-named
final generation and requires it to validate completely before installing state. A visible but
invalid highest generation is corruption, not permission to silently fall back to empty state or
an older generation after its required WAL prefix may have been retired.

The completion judge must use child JVM `Runtime.halt(86)` windows before the temporary write,
mid-write, after snapshot force, after rename, after snapshot-directory force, after the first WAL
delete, and after retirement-directory force. These are process-crash/file-reopen observations,
not power-loss proof. Deterministic failure injection must separately exercise write, file force,
rename, both directory forces, delete, snapshot read, and WAL-suffix read.

## Snapshot plus WAL suffix recovery

Recovery installs one valid `M09S1` snapshot and replays only the contiguous M08W1 records whose
WAL sequence is greater than `lastIncludedWalSequence`. The cut record is never applied twice and
the first suffix record is never skipped. An empty suffix is valid. A suffix may cross segment
boundaries. The terminal semantic digest, original duplicate results, next sequences, rule and mode
fences, and subsequent canonical command results must equal a fresh genesis replay of the same
full history.

If no snapshot exists, genesis recovery is allowed only while the WAL begins at sequence one. If a
prefix is missing and there is no valid published snapshot that covers it, recovery fails closed.
The runtime never silently starts with an empty book, bootstrap RuleSet, or default `OPEN` mode.

## Explicit recovery budget

The frozen completion profile permits at most 64 WAL records and 1,048,576 encoded WAL bytes after
the latest published snapshot cut. Before an append would exceed either configured bound, the
runtime must reject it before WAL mutation with `CHECKPOINT_REQUIRED`. A successful checkpoint
resets the suffix budget at its published cut. The judge proves this finite configured profile; it
does not claim an RTO, latency percentile, or universal production capacity.

## Whole-segment retirement

Only closed M08W1 segments whose greatest WAL sequence is less than or equal to the durably
published snapshot cut are eligible for retirement. The active segment and any segment crossing
the cut remain. Retirement starts only after snapshot-directory force completes. After deleting
eligible files, the WAL directory is forced before the maintenance operation reports success.

A crash between delete and directory force may reveal either namespace outcome on a real crash,
but both must remain recoverable from the already published snapshot. Reappearing covered segments
are ignored after full validation; missing uncovered segments fail closed. M09 performs no record
compaction and never truncates a crossing segment merely to improve the budget.

## Frozen RED and completion boundary

The start input is exactly 22 fixed scenarios plus a repository-owned SplitMix64 profile with seed
`5909`, 96 histories by 40 operations, four lanes with 24 histories each, 32 coverage obligations,
seven child-process crash windows, eight injected failure seams, 12 required executable semantic
mutants, and five tutorial permalinks. The fixed and generated resources are content-addressed by
the start runner. `./gradlew m09Check` must write a schema-valid `GOAL_NOT_IMPLEMENTED` report and
exit nonzero at the start ref.

Completion must add an independent snapshot/reference state model and a separate recovery ledger.
Two fresh generations must produce byte-exact canonical histories. Every required mutant must be
killed as `STUDENT_FAILURE` using a fresh runtime and strict snapshot/restart history; a throwing
control is `SYSTEM_ERROR` and never counts as a mutant kill. Evidence generation additionally
requires a clean HEAD carrying annotated `course/m09-complete`, with manifest source and every
artifact hash bound to that exact commit. M09 creates no product release.

## Explicit exclusions and stopping point

`FileChannel.force(true)` means only the documented JDK/OS barrier. The finite judge does not prove
physical-media durability, real power loss, disk-full behavior, a filesystem crash-consistency
matrix, formal correctness, or an RTO. M09 excludes online/concurrent snapshot, N-1 compatibility,
format migration, backup/archive, off-host restore, Aeron, replication, leader election, quorum,
failover, multiple shards, database recovery, throughput/latency qualification, and high
availability.

The stop point is still a local caller-serialized runtime. It can recover complete matching,
identity, and transcript state from one `M09S1` snapshot plus a bounded M08W1 suffix and can retire
only safely covered whole segments. It is not yet a Cluster runtime.
